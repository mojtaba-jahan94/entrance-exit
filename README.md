# سامانه مدیریت تردد و کارکرد (Entrance-Exit)

وب‌اپلیکیشن ثبت تردد روزانه، مدیریت شیفت شناور، محاسبه اضافه کاری، کسر کار، تاخیر، تعجیل و کاردکس مرخصی‌ها بر پایه تقویم هجری شمسی.

برای مطالعه مستندات فنی و ساختار برنامه، [راهنمای جامع پروژه](docs/PROJECT_GUIDE.md) را ببینید.

---

## امکانات واقعی سامانه

- **ثبت و پیگیری تردد:** ثبت لحظه‌ای ورود و خروج، تایمر زنده حضور و محاسبه زمان هدف خروج بر اساس شیفت کاری.
- **محاسبات خودکار:** محاسبه بلادرنگ کارکرد خالص (با کسر خودکار ناهار)، تاخیر ورود، تعجیل خروج، اضافه کار عادی، اضافه کار تعطیلات و کسر کار.
- **تقویم هجری شمسی و تعطیلات:** تقویم جلالی با نمایش مناسبت‌ها، روزهای تعطیل رسمی، جمعه‌ها و سال کبیسه.
- **کاردکس مرخصی‌ها:** ثبت مرخصی‌های ساعتی، نیم‌روز، روزانه، استعلاجی و بدون حقوق با محاسبه کسر از سهمیه ماهانه.
- **داشبورد و نمودارها:** نمایش خلاصه کارکرد ماه، تراز ساعت کاری، روزهای کاری و نمودار میله‌ای مقایسه‌ای روزانه.
- **جدول تردد ماهانه:** مرور رکوردهای ماه با امکان فیلتر بر اساس تاخیر، اضافه کاری، پنج‌شنبه‌ها و مرخصی‌ها به همراه حالت چاپ (Print-friendly).
- **خروجی داده‌ها:** تولید خروجی اکسل (`.xlsx`) به صورت جدول داده‌ای ساده و فایل پشتیبان JSON.
- **دو حالت ذخیره‌سازی و حل تعارض:** کارکرد کاملاً آفلاین در حافظه مرورگر (LocalStorage) یا همگام‌سازی ابری با دیتابیس Turso که داده‌ها قبل از ارسال با الگوریتم AES-256-GCM رمز می‌شوند. سیستم همگام‌سازی مجهز به قفل خوش‌بینانه بر پایه شماره نسخه (Optimistic Concurrency) و مکانیزم تعاملی حل تعارض چند دستگاهی (Conflict Resolution) است تا از بازنویسی تصادفی اطلاعات جلوگیری شود.
- **احراز هویت و امنیت پیشرفته:** ورود و ثبت‌نام مجهز به کنترل نرخ درخواست (Rate Limiting) در دیتابیس Turso با کلیدهای هش‌شده SHA-256 و فلفل (۵ شکست در ۱۵ دقیقه برای کاربر، ۲۰ شکست برای IP و ۵ ثبت‌نام در ساعت)، جلوگیری از شناسایی کاربران با هش ساختگی ثابت ضد حمله زمانی، توکن‌های کوتاه‌مدت ۷ روزه با قابلیت ابطال بلادرنگ نشست‌ها (`token_version`) پس از تغییر کلمه عبور، و نمایش تایمر هوشمند شمارش معکوس در صورت دریافت خطای ۴۲۹.

## قوانین پیش‌فرض شیفت و مرخصی

مقادیر زیر بر اساس پیکربندی پیش‌فرض سیستم در کد پیاده‌سازی شده‌اند و از بخش تنظیمات قابل ویرایش هستند:

- **شیفت شنبه تا چهارشنبه:**
  - ساعت رسمی: ۰۸:۳۰ تا ۱۷:۰۰ (حضور کل موظفی: ۵۱۰ دقیقه معادل ۸ ساعت و ۳۰ دقیقه).
  - بازه شناور ورود: ۰۸:۳۰ تا ۰۹:۳۰ (ورود در این بازه تاخیر محسوب نمی‌شود).
  - کسر ناهار/استراحت: ۳۰ دقیقه به صورت پیش‌فرض.
  - کارکرد مفید خالص روزانه: ۴۸۰ دقیقه (۸ ساعت).
  - ساعت خروج هدف: زمان ورود + ۵۱۰ دقیقه (مثلاً ورود در ۰۸:۴۰ منجر به خروج هدف در ۱۷:۱۰ می‌شود).
- **شیفت پنج‌شنبه:**
  - وضعیت پیش‌فرض: نیمه‌وقت (۴ ساعت معادل ۲۴۰ دقیقه موظفی).
  - استراحت/ناهار در روز پنج‌شنبه کسر نمی‌شود.
- **جمعه‌ها و تعطیلات رسمی:**
  - موظفی صفر دقیقه؛ هرگونه حضور به عنوان اضافه کار تعطیل با ضریب ۱.۸ ثبت می‌شود.
- **سهمیه مرخصی ماهانه:**
  - ۲.۵ روز کاری در هر ماه (معادل ۲۰ ساعت کارکرد مفید خالص بر مبنای روز ۸ ساعته).

## ظاهر و رابط کاربری

رابط کاربری برنامه بر اساس سیستم طراحی مینیمال با پالت پیش‌فرض **Nordic** (ترکیب رنگ‌های زغال چوب، کرم برفی، خاکستری فیورد و چوب گرم) پیاده‌سازی شده است. ناوبری میان بخش‌ها از طریق داک کپسولی پایین صفحه (`BottomCapsuleDock`) انجام می‌شود و بخش تنظیمات در قالب یک صفحه مجزا (`SettingsPage`) در دسترس کاربر قرار دارد.

## پیش‌نیازها

- **Node.js:** نسخه `^20.19.0 || >=22.12.0` (مطابق فیلد `engines.node` در پکیج `vite`)
- **مدیر بسته:** فقط `npm`

## نصب و اجرا

۱. دریافت مخزن و نصب وابستگی‌ها:
```bash
npm install
```

۲. اجرای برنامه در محیط توسعه:
```bash
npm run dev
```
سپس آدرس `http://localhost:5173` را در مرورگر باز کنید.

۳. اجرای تست‌های واحد (Vitest):
```bash
npm test
```

۴. اعتبارسنجی کد با لینتر (Oxlint):
```bash
npm run lint
```

۵. بیلد نسخه پروداکشن:
```bash
npm run build
```
خروجی کامپایل‌شده در پوشه `dist` ایجاد می‌شود.

## متغیرهای محیطی

برای استفاده از بخش ابری و توابع سرورلس، فایل `.env` را بر اساس `.env.example` بسازید:

| نام متغیر | نوع | پیش‌فرض / توضیحات |
| :--- | :--- | :--- |
| `JWT_SECRET` | **اجباری** | کلید محرمانه تصادفی (حداقل ۳۲ کاراکتر) برای امضای توکن‌های نشست احراز هویت و فلفل (Pepper) کلیدهای Rate Limiting |
| `ALLOWED_ORIGIN` | اختیاری | آدرس دامنه مجاز وب‌سایت برای هدر CORS (در صورت عدم تنظیم، به مبدأ همان درخواست یا لوکال محدود می‌شود) |
| `TURSO_DATABASE_URL` | اختیاری | آدرس اتصال پایگاه داده LibSQL / Turso (مثال: `libsql://your-db.turso.io`) |
| `TURSO_AUTH_TOKEN` | اختیاری | توکن احراز هویت دیتابیس Turso |

*نکته: در صورت عدم تنظیم متغیرهای ابری، برنامه در حالت محلی آفلاین بدون محدودیت کار خواهد کرد.*

## معماری خلاصه

- **فرانت‌اند:** React 19، TypeScript، Tailwind CSS و Vite.
- **تقسیم کد (Code Splitting):** استفاده از `React.lazy` برای بارگذاری ماژول‌های سنگین و بارگذاری پویای کتابخانه SheetJS (`xlsx`) فقط در زمان کلیک روی دکمه خروجی اکسل.
- **بک‌اند سرورلس:** توابع مبتنی بر Vercel Serverless Functions مستقر در پوشه `api/`:
  - `api/status.ts`: بررسی وضعیت سلامت سرویس و اتصال به دیتابیس.
  - `api/auth/`: اندپوینت‌های ثبت‌نام، ورود، دریافت نشست و تغییر کلمه عبور مجهز به کنترل نرخ درخواست (Rate Limiting) در دیتابیس، توکن‌های ابطال‌پذیر ۷ روزه (`token_version`) و هش ساختگی ضد حمله زمانی.
  - `api/sync/`: اندپوینت‌های ذخیره و بارگذاری داده‌های رمزگذاری‌شده کاربر مجهز به قفل خوش‌بینانه (`baseVersion`) و مدیریت خطای تعارض (HTTP 409 Conflict).
- **ذخیره‌سازی، رمزنگاری و حل تعارض:** کلاینت می‌تواند داده‌ها را در LocalStorage ذخیره کند یا از طریق اندپوینت‌های `sync` با دیتابیس ابری Turso هماهنگ نماید. داده‌ها پیش از ارسال به سرور با کلید محلی و الگوریتم AES-256-GCM رمزگذاری می‌شوند. جدول `user_cloud_data` دارای ستون شماره نسخه (`version`) با مهاجرت خودکار و امن است؛ هر ذخیره‌سازی به صورت اتمی نسخه ارسالی را تطبیق داده و در صورت وجود نسخه جدیدتر در دستگاه دیگر، ذخیره خودکار متوقف شده و پنجره تعاملی حل تعارض با گزینه‌های استفاده از داده ابری، جایگزینی یا تعویق برای کاربر باز می‌شود.

## استقرار روی Vercel

پروژه به صورت بومی با Vercel سازگار است. برای دیپلوی:
۱. مخزن را به حساب کاربری Vercel متصل کنید.
۲. در بخش **Environment Variables**، متغیر اجباری `JWT_SECRET` و در صورت نیاز `TURSO_DATABASE_URL`، `TURSO_AUTH_TOKEN` و `ALLOWED_ORIGIN` را وارد کنید.
۳. دستور بیلد به صورت پیش‌فرض `npm run build` است.
